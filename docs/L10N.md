# Come si scrive una stringa, da adesso

Questo file è la specifica operativa della localizzazione dell'app. Vale per
chiunque tocchi testo visibile all'utente in `android/app/src/main`.

Il README racconta *perché* le cose stanno così (sezione **3b. Le lingue**); qui
c'è solo il *come*.

## La regola in una riga

**Nessuna frase rivolta all'utente vive in un file `.kt`.** Vive in
`res/values/strings.xml` (italiano, lingua base) e in `res/values-en/strings.xml`
(inglese), e il codice la nomina.

I due XML sono **generati**: la sorgente sono le tabelle in `tools/l10n/*.tsv`.

```powershell
python tools\l10n-build.py            # rigenera i due XML
python tools\l10n-build.py --check    # verifica soltanto, esce 1 se sono indietro
```

Nessuno modifica `strings.xml` a mano: la modifica verrebbe persa alla
rigenerazione successiva, e sarebbe invisibile al test che confronta le lingue.

## Cosa NON è una stringa da tradurre

| Resta com'è | Esempi |
|---|---|
| identificatori di protocollo, codici, chiavi JSON | `"tool/call"`, `"file_path"`, `"directory-exists"`, `"unauthorized"` |
| rotte e nomi di parametro | `"/mobile/sessions"`, `"seq"`, `"index"` |
| nomi di modello e di strumento dell'host | `"pwsh"`, `"read"`, `"todo_write"` |
| descrizioni KDoc e commenti | non si traducono: sono documentazione del codice |
| messaggi in `Log.d(...)` | vanno allo sviluppatore, non all'utente |
| unità già neutre | `"MB"`, `"B"`, `"KB"`, `"ms"` |
| punteggiatura e separatori | `" · "`, `"—"`, `"…"`, `"OK"` |

Nel dubbio: *lo vedrebbe un utente sul telefono?* Se sì, è una stringa.

## Il nome

`prefisso_nome`, tutto minuscolo, `snake_case`, prefisso dell'area a cui il file
appartiene. Il nome dice **cosa dice** la stringa, non dove viene usata.

```
pair_title          "Collega al tuo harness"
session_new         "Nuova chat"
chat_send           "Invia"
tool_family_read    "Lettura"
```

Mai `_message`, `_text`, `_label` in coda: sono rumore.

Le chiavi **non si duplicano mai** fra due tabelle, nemmeno con lo stesso testo:
il generatore si ferma. Se una stringa serve a due aree, appartiene a una sola e
l'altra la referenzia.

## I segnaposto

Posizionali, sempre — l'inglese riordina le parole:

```xml
<string name="workspace_remove_question">Rimuovere «%1$s» dai progetti?</string>
<plurals name="session_slice_more">
    <item quantity="one">Vedi l\'altra chat</item>
    <item quantity="other">Vedi le altre %1$d chat</item>
</plurals>
```

- `%1$s` testo, `%2$d` intero, e così via.
- Un conteggio usa `<plurals>`: l'inglese distingue *one* da *other*, l'italiano
  no, e scrivere `%1$d chat` in una `<string>` è la differenza che si vede solo
  in inglese.
- Un apostrofo nell'XML si scrive `\'` (`l\'altra`). `&` è `&amp;`, `<` è
  `&lt;`. Le virgolette `«»` restano caratteri normali.

## Nel codice Compose

```kotlin
Text(stringResource(R.string.session_new))
Text(stringResource(R.string.workspace_remove_question, workspace.title))
Text(pluralStringResource(R.plurals.session_slice_more, hidden, hidden))
```

Import: `androidx.compose.ui.res.stringResource` e
`androidx.compose.ui.res.pluralStringResource`.

## Fuori da Compose: `TextRef`

Una frase **scelta** (quale rifiuto significa un codice d'errore, come si chiama
uno stato) si decide nel ViewModel o nel livello `data`, e lì non c'è un
`Context`: si restituisce un `TextRef` — l'id della risorsa più i suoi argomenti
— che un composable scioglie con `textResource(ref)` (in `ui/Text.kt`).

```kotlin
// nel ViewModel
problem = ConnectionProblem(error.code, TextRef.of(R.string.error_unauthorized))
problem = ConnectionProblem(error.code, TextRef.of(R.string.error_folder_exists, name))

// in un composable
ProblemBanner(message = textResource(problem.message), onDismiss = { … })
```

Dove un `Context` c'è ma la composizione no — un avviso scritto in una mappa
prima che qualcuno lo legga, un file scritto nella cartella Download — si usa
`TextRef.resolve(context)`, da `data/TextRef.kt`.

`TextRef.Raw` porta la frase che ha scritto **l'host**: non si traduce e non si
riscrive. Sostituirla con una inventata sarebbe peggio che mostrarla.

## Il livello `data` non produce testo

Produce la *struttura* che il testo descrive. Un enum, una data class, un
booleano:

```kotlin
enum class ChatStatus { Completed, Running, Failed, Stopped, Idle }
// e in ui/SessionsScreen.kt:
val label = stringResource(
    when (status) {
        ChatStatus.Completed -> R.string.status_completed
        // …
    }
)
```

È deliberato: così le regole restano verificabili su JVM senza telefono, e le
parole verificabili contro `strings.xml` senza compilare l'app — `StringsXml`,
nei test, legge il file con `DocumentBuilderFactory` e nient'altro.

## Le tabelle di traduzione

Una riga per stringa, tre colonne separate da tabulazioni, **senza intestazione**:

```
chiave<TAB>italiano<TAB>inglese
session_new	Nuova chat	New chat
session_slice_more	Vedi l\'altra chat|Vedi le altre %1$d chat	See the other chat|See the other %1$d chats
```

- l'italiano è il testo **esatto** che c'era nel codice, apostrofi e spazi
  compresi (il generatore non rimuove gli spazi ai bordi: `" · %1$s"` è una
  stringa legittima);
- l'inglese è la traduzione, con lo stesso tono: l'app parla all'utente come una
  persona competente, non come un manuale. Frasi intere, non etichette troncate;
- niente `\n` dentro un valore: una frase che va a capo è due frasi;
- in una `plurals` le forme si separano con `|`, nell'ordine `one|other`.

Il generatore rifiuta: chiave duplicata, valore vuoto, nome non `snake_case`,
segnaposto che l'inglese perde o aggiunge, numero di forme plurali diverso fra le
due lingue, virgolette doppie, `</` dentro un valore, tabulazione o a capo in un
valore.

## Aggiungere una lingua

1. la cartella `res/values-<tag>/strings.xml` — generata, quindi si aggiunge una
   terza colonna alle tabelle invece di scrivere il file;
2. `<locale android:name="<tag>" />` in `res/xml/locales_config.xml`;
3. una voce in `data/LanguageMode.kt` (`id`, `tag`) e i due nomi in
   `tools/l10n/language.tsv`;
4. il tag in `resourceConfigurations` di `app/build.gradle.kts`.

Il nome della lingua **non** sta in `LanguageMode`: un'etichetta è parte di una
frase nella lingua in uso, e la sola eccezione è il segmento che sceglie la
lingua, che si scrive nella lingua che seleziona.

`TranslationParityTest` fa il resto: se una chiave manca, il test lo dice prima
dell'APK. Senza quel test una traduzione incompleta non fallisce — Android
risponde con la lingua base, e resta una frase italiana in mezzo a quelle
inglesi, che nessuno nota e nessuno strumento segnala.
